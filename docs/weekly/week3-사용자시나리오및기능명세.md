# 3주차 — 사용자 시나리오 및 기능 명세

**프로젝트**: G-SCM 차세대 전환 Agent
**범위**: 전환 프로그램 **1단계 = 서버(Java/XSQL → Spring/MyBatis) 전환**

---

## 1. 판정 체계 표준 (모든 시나리오 공통)

시나리오별로 "성공/실패"를 다르게 부르면 결과를 비교할 수 없다. **판정어를 아래 6개로 고정**하고, 도구·DB·문서가 전부 이 용어만 쓴다.

| 판정 | 의미 | 후속 조치 | 저장/승인 가능 여부 |
|---|---|---|---|
| **PASS** | 해당 검사 항목을 통과 | 없음 | 가능 |
| **WARNING** | 동작은 하지만 사람이 봐야 할 사항 (예: DTO 필드를 역추출하지 못해 비어 있음) | 리뷰 시 확인 | **가능** (승인자 판단) |
| **BLOCKER** | 이 상태로는 정상 동작을 보장할 수 없음 (예: 미지원 DB 동사, 호출 대상 미존재, 포팅 스텁 잔존) | 수리 루프 대상 또는 수동 처리 | **불가** (해소 전까지 완료 아님) |
| **FAIL** | 검사 자체가 실패 (컴파일 실패, XML 파싱 실패) | 원인 분류 후 수리 또는 원본 재확보 | **불가** |
| **SKIPPED** | 도구가 지원하지 않는 케이스여서 검사하지 않음 (예: 동적 SQL 태그가 있는 문장의 차등 테스트) | 수동 검증 필요로 기록 | 가능 (미검증으로 표기) |
| **APPROVED** | 사람이 결과를 검토하고 반영을 승인 | 저장 진행 | — |

**규칙**
1. `SKIPPED`를 `PASS`로 집계하지 않는다. 검사 안 한 것과 통과한 것은 다르다.
2. `BLOCKER`가 하나라도 있으면 그 화면은 **완료가 아니다.** 빌드가 통과해도 마찬가지다.
3. `APPROVED`는 자동으로 부여되지 않는다. **사람이 버튼을 눌러야만** 부여된다.
4. 원본 결함에서 비롯된 실패는 `ORIGINAL_BUG`으로 따로 표시해, 도구의 실패와 구분한다.

## 2. 사용자 시나리오

### SC-001 — 화면 묶음을 한 번에 전환한다

**사용자**: 전환 투입 백엔드 개발자
**목적**: 담당 화면들의 서버 로직을 자동 전환하고, 손봐야 할 부분만 골라내고 싶다

| 항목 | 내용 |
|---|---|
| **사전 조건** | 전환 대상 화면들의 AS-IS 소스(P/F/D BizUnit + XSQL)가 한 폴더에 있다 |
| **입력 예시** | 폴더 경로 지정 → 목록에서 전환할 화면 선택 (기본값 전체) → "파이프라인 시작" |
| **기대 출력** | ① 단계별 진행 상황(현재 몇 단계 / 총 몇 건 중 몇 건 남음)<br>② 화면별 결과 요약 — 생성된 파일 목록, 판정(PASS/WARNING/BLOCKER), 위험도<br>③ 전체 요약 — 빌드 결과, 중복·미사용 함수 후보, 영향도 대시보드 |
| **성공 기준** | ⓐ 선택한 화면 전부에 대해 Api/Service/Store/Dto/Mapper 5종이 생성됨<br>ⓑ 규칙 기반 생성물의 컴파일 통과율 95% 이상<br>ⓒ 각 화면의 판정이 위 표준 6개 중 하나로 명확히 표시됨<br>ⓓ **승인 전에는 결과물 폴더에 어떤 파일도 생기지 않음** |

**정상 흐름**
1. 폴더 지정 → 도구가 화면 단위로 파일을 묶어 목록 표시
2. 전환할 화면 선택 후 시작
3. 도구가 **변환 계획을 먼저 파일로 고정**한다 (무엇을 만들 것인지, LLM을 몇 번 부를 것인지)
4. 규칙 기반 변환 → LLM 포팅 → 정적 검증 → (실패 시) 수리 재시도 → 품질 스캔 → 참고용 대안 제안
5. 저장 없이 **임시 사본**에 결과를 겹쳐 써서 전체 교차 분석과 빌드 검증까지 수행
6. 사용자가 결과를 확인하고 **"승인하고 저장"** 클릭 → 이때 처음으로 실제 반영

**예외 흐름**

| 예외 | 도구 동작 | 사용자에게 보이는 것 |
|---|---|---|
| E1. AS-IS 원본이 컴파일되지 않는 상태 | 원본을 **고치지 않고 보존**. 계획 단계에서 결함 신호를 표시하고 재설계 후보로 분류 | "원본이 그대로는 컴파일되지 않습니다 (중괄호 불일치 N건)" 경고 + 재설계 트랙 후보 표시 |
| E2. 화면에 P/F/D/XSQL 중 일부가 없음 | 없는 조각은 계획서에 `없음`으로 기록하고, 그 조각에 의존하는 산출물은 생성하지 않음 | 계획 탭에 조각별 존재 여부 표 |
| E3. LLM 호출 실패(네트워크·게이트웨이 오류) | 상한 내에서 재시도. 그래도 실패하면 해당 메서드를 **스텁 상태로 남기고** BLOCKER 기록 | "포팅 실패 — 수동 처리 필요" + 인수인계 문서에 사유 기재 |
| E4. LLM이 존재하지 않는 필드를 만들어냄 | 원본 필드 목록과 대조해 **자동 차단**, BLOCKER 기록 | 해당 제안을 반영하지 않고 차단 사유 표시 |
| E5. 지원하지 않는 DB 동사(조회 외 등록/수정/삭제) | 추측으로 코드를 만들지 않고 **미지원으로 표시** + 해당 메서드에 처리 안내 주석 | 계획 단계에서 미리 경고 → 늦게 발견되지 않음 |
| E6. 검증에서 BLOCKER 발생 | 정해진 라운드 수만큼 수리 재시도. 예산 소진 시 포기하고 사유를 남김 | "수리 N회 시도 후 미해소" + 남은 문제 목록 |
| E7. 사용자가 승인하지 않음 | 아무것도 저장하지 않고 종료. 임시 사본은 삭제 | 결과물 폴더 무변경 |

### SC-002 — 변환 결과가 원본과 같은 값을 내는지 확인한다

**사용자**: QA / 전환 개발자
**목적**: "변환됐다"가 아니라 **"맞다"** 를 확인하고 싶다

| 항목 | 내용 |
|---|---|
| **사전 조건** | 변환 결과가 있고, 대상 데이터베이스에 접속 가능하다 |
| **입력 예시** | 화면 상세 화면에서 "차등 테스트" 실행 |
| **기대 출력** | 조회문 단위로 AS-IS 결과와 TO-BE 결과의 비교 판정 (PASS / SKIPPED / FAIL) + 사유 |
| **성공 기준** | ⓐ 동일 입력에 대해 양쪽 결과가 완전히 일치하면 PASS<br>ⓑ 도구가 지원하지 않는 케이스는 **PASS가 아니라 SKIPPED**로 정직하게 표시<br>ⓒ 테스트를 위해 생성한 데이터는 **실행 후 반드시 삭제**되어 흔적이 남지 않음 |

**정상 흐름**
1. 조회문의 조건절을 정적으로 읽어 그 조건을 만족하는 **최소 테스트 데이터를 자동 생성**
2. 같은 입력으로 AS-IS 문장과 TO-BE 문장을 각각 실행
3. 결과 비교 → 판정 기록
4. `finally` 구간에서 테스트 데이터를 **항상 삭제**

**예외 흐름**

| 예외 | 도구 동작 |
|---|---|
| E1. 동적 조건 태그가 있는 문장 | 조건 평가 엔진이 없으므로 `SKIPPED` + 사유 기록. 임의 값으로 실행하지 않는다 |
| E2. 대상 테이블이 스키마에 없거나 컬럼이 다름 | `FAIL`로 기록하되 **도구 결함이 아니라 환경/스키마 문제**로 분류 |
| E3. 원본 SQL 자체에 문법 오류 | `FAIL` + `ORIGINAL_BUG` 표시. 이건 **전환 도구가 찾아낸 기존 결함**이다 |
| E4. 테스트 데이터 자동 생성이 불가능한 조건(다중 테이블 조인, 범위/서브쿼리 조건) | 추측 데이터를 넣지 않고 `SKIPPED` |

### SC-003 — 이 함수를 바꾸면 어디가 영향받는지 묻는다

**사용자**: 전환 개발자 / PL
**목적**: 특정 함수를 수정·삭제하기 전에 영향 범위를 알고 싶다

| 항목 | 내용 |
|---|---|
| **사전 조건** | 매핑 그래프가 구축되어 있다 (파이프라인을 다시 돌릴 필요 없음) |
| **입력 예시** | "영향도 질의" 클릭 → 함수명 입력 (예: 특정 데이터 조회 함수) → 조회 |
| **기대 출력** | ① 이 함수를 직접·간접적으로 호출하는 함수 목록(호출 깊이 포함)<br>② 영향받는 화면 목록<br>③ 영향받는 트랜잭션(nctRid) 목록<br>④ 값의 출처 표시 (확정값인지 대체 경로로 채운 값인지) |
| **성공 기준** | ⓐ 수동으로 코드를 따라가 확인한 결과와 일치<br>ⓑ 호출자가 없으면 "호출자 없음"을 명시하고, 그것이 곧 미사용을 뜻하지 않는다는 한계를 함께 표시<br>ⓒ **LLM을 사용하지 않는다** — 그래프 순회로 정확한 답이 나오므로 추론을 섞지 않는다 |

**예외 흐름**

| 예외 | 도구 동작 |
|---|---|
| E1. 존재하지 않는 함수명 | "해당 함수를 찾을 수 없음" 안내. 유사 이름을 추측 제시하지 않음 |
| E2. 호출자가 0건 | 결과를 그대로 보여주되, **호출 관계 수집의 한계**(특정 호출 패턴은 그래프에 잡히지 않을 수 있음)를 함께 표시 |
| E3. 트랜잭션 정보가 비어 있음 | 별도 매핑표에서 보완하고, **어느 출처에서 온 값인지 표시**해 숨기지 않는다 |

### SC-004 — 자동으로 안 된 부분만 넘겨받는다

**사용자**: 후속 작업자 / 외주 개발자
**목적**: "이 화면에서 자동으로 안 된 게 뭐고, 내가 뭘 해야 하나"를 한 문서로 보고 싶다

| 항목 | 내용 |
|---|---|
| **사전 조건** | 해당 화면의 파이프라인이 1회 이상 수행됨 |
| **입력 예시** | 화면 상세 → "인수인계" 탭 |
| **기대 출력** | 화면별 마크다운 문서 — ① 자동 변환을 신뢰하면 안 되는 이유 ② 원본 결함 경고 ③ 포팅 실패로 스텁이 남은 함수 ④ BLOCKER ⑤ WARNING ⑥ 생성 산출물 표 ⑦ 반드시 사람 리뷰가 필요한 함수 |
| **성공 기준** | ⓐ 이슈마다 **확인된 조치 방법**이 붙어 있음<br>ⓑ 조치 방법이 정의되지 않은 이슈 유형에는 **없는 처리법을 지어내지 않고** 원본 메시지만 표시<br>ⓒ 도구 UI를 열지 않아도 문서만으로 작업 가능 |

## 3. 기능 명세 요약

| 기능 | 입력 | 출력 | 판정 |
|---|---|---|---|
| 매핑 그래프 구축 | AS-IS 소스 폴더 | 화면↔트랜잭션↔함수↔SQL 그래프 | PASS / WARNING(미해결 매핑 존재) |
| 변환 계획 수립 | 화면 단위 소스 묶음 | 계획 파일(대상 조각·예상 산출물·LLM 호출 대상·트랙 신호) | PASS |
| 규칙 기반 변환 | 계획 + 소스 | Api/Store/Dto 골격, Mapper | PASS / FAIL |
| LLM 포팅 | 대상 함수 + 호출 계약 | Service 함수 본문 | PASS / BLOCKER(스텁 잔존) |
| 정적 검증 | 생성 결과 | 항목별 검사 결과 | PASS / WARNING / BLOCKER |
| 수리 루프 | 검증 실패 내역 | 재생성된 함수 본문 | PASS / BLOCKER(예산 소진) |
| 빌드 검증 | 결과물 트리 | 컴파일 결과 | PASS / FAIL |
| 차등 테스트 | 조회문 + DB | 결과 비교 | PASS / SKIPPED / FAIL |
| 영향도 분석 | 함수명 | 호출자·화면·트랜잭션 | — (조회) |
| 인수인계 문서 | 파이프라인 결과 | 화면별 마크다운 | — (산출) |

## 반영 사항 (2주차 피드백 대응)

| 2주차 지적 | 반영 내용 |
|---|---|
| 문서 구조/가독성 — 제안 순서대로 재배치 | 2주차 문서를 개요→문제정의→목표사용자→8주범위→핵심가설→성공지표→핵심기능→리스크및대응→예상산출물 순으로 재작성 |
| 범위 과다 — 장기 비전과 8주 PoC 분리 | 2주차 §4에 8주 vs 장기 비전 표 신설. "8주 안에 하지 않는 것"을 명시 |
| 핵심 가설 2~3개를 명시하라 | 2주차 §5에 H1/H2/H3 신설. 각각 검증 방법과 성공 기준 포함 |
| **KPI 수치 충돌** (표와 기대효과의 수치가 다름) | 공수 절감 수치를 **65~70% 하나로 통일**. 근거는 화면 유형별 차등 추정. 기준선이 미실측 가정임을 명시 |
| 성공 기준 측정 방법 부족 → 다층 지표 필요 | 2주차 §6을 L1 구조 / L2 문법 / L3 기능 / L4 공수 **4개 층**으로 재구성. 측정 규칙(유형 분류·샘플 수·작업 정의·사람 개입 시간 포함)을 별도 명시 |
| 리스크-대응 1:1 연결 | 2주차 §8을 R1~R7 1:1 표로 재작성 |
| 산출물 선명화 | 2주차 §9에 구분별 산출물 표 신설 |
| 문서 끝에 "반영 사항"을 정리해 달라 | **이 절 신설.** 이후 모든 주차 문서에 동일 형식으로 포함 |
