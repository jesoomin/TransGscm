# 시연 영상 — 구성과 규격

> **영상은 하나다.** 5분 이내에 **장표를 띄워 설명하면서 시연까지** 마쳐야 한다.
> 컷별 대사·편집 지시는 `docs/weekly/assets/presentation-kit.html`의 **5분 촬영 대본** 절에 있다.
> 이 문서는 그 구성의 근거와 규격만 남긴다.

## 1. 제출 규격

| 항목 | 값 |
|---|---|
| 길이 | **5분 이내** (초과분은 평가 제외) |
| 형식 | MP4 |
| 용량 | **500MB 이하** |
| 파일명 | `[사번]_[성명]_시연영상.mp4` |
| 음성 | 선택 (자막으로 대체 가능) |

## 2. 가이드가 못 박은 배점 신호

- *"UI에서 처리 결과만 보여주는 경우 → 기술 구현 확인이 어려워 평가에 불리"*
- *"핵심 로그가 담긴 터미널/콘솔 화면은 반드시 포함"*
- *"Agent의 추론 과정이 보여지는 로그로 증명해야 기술 깊이를 평가받을 수 있다"*
- 필수 장면 3종 — **시나리오 소개(30초) · Agent 추론 로그(핵심) · 최종 결과 확인(30초~1분)**
- **편집 능력 자체도 평가 요소** — "핵심만 추려 5분 안에 전달하는 것"

> **가이드의 `Planning: 5-step plan generated`는 예시 문구다.** "고수준 로그란 이런 것"을
> 설명하려고 든 것이지 그대로 쓰라는 뜻이 아니고, 우리 출력에도 없다. 요구의 실체는
> *단순 `Thinking... → Tool Call...`이 아닌, 판단이 보이는 로그*이며, 우리 대응물은
> `PLAN` · `DECIDE` · `THINK` · `REFLECT` 네 줄이다. **화면에 실제로 뜨는 문장만 쓴다.**

## 3. 5분 배분

장표와 로그가 같은 5분을 나눠 쓴다. 로그가 주인공이라는 원칙은 유지하되, 장표가 앞에서
구조를 세워주면 뒤의 로그가 설명 없이 읽힌다.

| 시각 | 화면 | 구간 | 길이 |
|---|---|---|---|
| 0:00 | 장표 1 | 문제와 에이전트 구조 | 35초 |
| 0:35 | 장표 2 | 추론 순환 — 뒤에 볼 로그의 지도 | 30초 |
| 1:05 | 터미널 | 계획 수립 (`PLAN`/`DECIDE`) | 30초 |
| 1:35 | 터미널 | 계약 주입 + `THINK` ★ | 25초 |
| 2:00 | 터미널 | 정적 검증 — BLOCKER 10건 | 20초 |
| 2:20 | 터미널 | **선별 게이트 + ToT 채점** ★★ | 35초 |
| 2:55 | 터미널 | 정답키 대조 + 재검증 10→1 | 30초 |
| 3:25 | 터미널 | 동작 일치 + 실행 요약 | 25초 |
| 3:50 | UI | 승인 게이트 | 15초 |
| 4:05 | 장표 3 | 난제와 결과 수치 | 30초 |
| 4:35 | 장표 3 | 2차 적용 + 마무리 | 25초 |

**장표 2:00(40%) · 터미널 2:45(55%) · UI 0:15(5%)**
**추론 로그 구간 1:05~3:25 = 2분 20초(47%)** — 가이드가 배점을 몰아둔 구간을 넘겨 잡았다.

## 4. 화면 구성

**장표와 터미널을 나란히 놓지 않는다.** 터미널이 작아지면 로그를 읽을 수 없고, 그러면 이
영상의 근거가 통째로 사라진다. 장표 구간은 장표 전체화면, 시연 구간은 터미널 전체화면으로
전환한다.

- 터미널: UTF-8(`chcp 65001`) · 폭 100컬럼 이상 · **글꼴 16pt 이상** · `cls` 후 시작
- 장표: 슬라이드 쇼 모드, 발표자 노트 창이 잡히지 않게 확인
- Streamlit: 미리 띄우고 **실행 완료 상태**로 대기

## 5. 대기 시간 제거

가이드가 *"긴 대기는 잘라내거나 배속"*하라고 한다. 편집보다 **재촬영이 깔끔하다.**

```
python -m agents.run_pipeline <평가 세트> \
    --screens PLA087,PLA089,PLA093,PLA096,PLA100 --no-ai-recommend --cache
```

`--cache`로 한 번 돌려 응답을 받아두면 두 번째 실행이 **약 40초 → 약 11초**로 줄어든다.
로그는 동일하게 전부 출력되므로 대기 없는 화면을 그대로 찍을 수 있다.

남는 11초는 **동작 일치 검증이 실제로 javac를 돌리는 시간**이다. 시연의 핵심 단계라
건너뛰지 않는다 — `--fast`는 개발 중 반복용이고 **녹화에는 쓰지 않는다.**

> 캐시 실행은 같은 입력에 같은 응답을 재생하는 것이라 결과가 조작되지 않는다. 질문이 나오면
> 그대로 말하면 된다 — *"응답 캐시를 켜고 두 번째 실행을 녹화했고, 로그와 결과는 첫 실행과
> 동일합니다."*

## 6. 용량

| 비트레이트 | 5분 용량 | 판단 |
|---|---|---|
| 8 Mbps | 약 300 MB | **권장** — 1080p 30fps H.264에서 로그가 충분히 선명 |
| 10 Mbps | 약 375 MB | 확대 컷이 많으면 이쪽 |
| 12 Mbps | 약 450 MB | 한계 근접, 음성까지 넣으면 위험 |

**1920×1080 · 30fps · H.264 · 8~10 Mbps.** 60fps는 필요 없다 — 용량만 두 배가 되고
로그 가독성은 그대로다.

## 7. 두 소스 세트 — 말로 구분한다

| 세트 | 정체 | 영상에서의 역할 |
|---|---|---|
| 실제 전환 대상 (PLA045~050) | 운영 소스 트리 | "무엇을 전환하는가" |
| 정답키 평가 세트 (PLA087~100) | 결함을 주입하고 **정답키를 제공**하는 채점용 | "제대로 잡아냈는가" |

실제 전환 대상에는 정답이 없다. 탐지·교정 성능을 *증명*하려면 정답이 확정된 세트가 있어야
한다. **섞어 말하면 틀린 주장이 된다.**

## 8. 리스크와 대비

| 리스크 | 대비 |
|---|---|
| 녹화 중 LLM Gateway 장애 | `--cache`로 이미 받아둔 응답이 있으면 그대로 재생된다. 없으면 `--dry-run`으로 계획~검증 구간은 재현 가능 |
| 5분 초과 | 4:05~5:00 장표 구간을 정지 슬라이드 + 자막으로 대체해 20초 절약 |
| 로그가 화면 폭을 넘어 접힘 | 폭 100컬럼 이상, `--no-color`로 폭 절약 가능 |
| 콘솔 인코딩 | UTF-8이 아니면 로그가 중단된다 — `chcp 65001` |
| 터미널 글자가 작아 안 읽힘 | 녹화본을 **휴대폰으로 재생해** 확인 |
