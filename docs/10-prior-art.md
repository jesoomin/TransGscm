# 선행 연구 참조와 차용 지점

이 문서는 그동안 @docs/06-mentor-feedback.md(§A~§J)와 @docs/03-kickoff-plan.md 곳곳에 흩어져
있던 선행 연구 참조를 한자리에 모은 것이다. **새로운 주장을 하지 않는다** — 이미 코드로 확인해
기록해 둔 차용·기각 판단을 출처별로 재배치했을 뿐이다.

정리 기준 세 가지:
1. **무엇을 차용했나**를 "이 프로젝트의 어느 파일에 있는가"까지 적는다. 개념만 인용하고
   구현이 없으면 그렇게 적는다.
2. **무엇을 기각했나**와 그 이유를 함께 적는다. 안 쓴 것도 판단의 결과다.
3. **수치는 출처를 구분한다.** 논문 원문을 직접 확인한 값과 멘토 코멘트가 인용한 값이 다른
   경우가 실제로 있었다(아래 §1 참고).

## 1. AlphaTrans — 분해·순서·계약

**직접 확인한 원문**: [arxiv 2410.24117v4](https://arxiv.org/html/2410.24117v4) (FSE 2025).

**수치 출처 구분(중요)**: 원문을 직접 확인한 값은 **문법 정확도 96.40% vs 기능 동등성 25.14%**
다. 멘토 코멘트(@docs/06-mentor-feedback.md §A)는 99.1% vs 25.8%로 인용했는데, 이 프로젝트의
문서·발표에는 **직접 확인한 96.40 / 25.14를 쓴다**. 어느 쪽이든 결론(문법과 기능 사이에 큰
간극이 있다)은 같지만, 인용 수치를 검증 없이 옮기지 않는다.

| 원 패턴 | 이 프로젝트의 적용 | 구현 위치 |
|---|---|---|
| 프로그램 분석으로 fragment 분해 | 화면을 통째로 넣지 않고 `.BIZUNIT` / P / F / D / XSQL **5개 fragment**로 분리 | `source_scan.py`, `conversion_plan.py` |
| 콜그래프 역순 번역 | XSQL → Store → Service → Api 순서. 하위가 확정돼야 상위 시그니처가 안 흔들린다 | 파이프라인 단계 순서 |
| 스켈레톤 우선 구성 | 클래스·메서드·DTO 골격을 **규칙 기반으로 100% 확정한 뒤** LLM은 빈 본문만 채운다 | `skeleton_gen.py` → `port_one_screen_method_node` |
| 조각마다 콜러/콜리 메타데이터 전달 | 피호출자 계약을 **JSON 객체**로 프롬프트에 주입 | `workflow_graph._callee_note()` |
| 실패분 리포트를 정상 산출물로 | 화면별 인수인계 문서 자동 생성 | `handoff_report.py` |

**차용하며 실제로 있었던 일**: 계약 주입은 처음엔 자유 텍스트였다. 이를 JSON 계약 객체로 바꾸며
`return_type`과 `cardinality_mismatch`를 정확히 채우려다 **Store 카디널리티 결함**(원본은 다건
조회인데 TO-BE Store가 단건 `selectOne`)을 발견했다 — 6개 실화면 전부, 화면당 4~10건. 계약을
명시화한 작업이 결함 탐지기 노릇도 한 사례다(@docs/03-kickoff-plan.md 2026-09-10).

**AlphaTrans와 갈리는 지점**: AlphaTrans는 레포의 **기존 테스트**로 기능 동등성을 검증한다.
이 프로젝트의 AS-IS에는 테스트가 없어서 그 경로가 막혀 있었고, 그래서 `equivalence_test.py`
(최소 실행 하네스)를 직접 만들어야 했다.

## 2. ReCodeAgent — 역할 분리와 계획 영속화

**직접 확인한 원문**: [arxiv 2604.07341v1](https://arxiv.org/html/2604.07341v1).
참고 수치: Java→C# 기준 컴파일률 55%, 통과율 46% — **첫 시도 통과를 전제로 계획을 짜면 안 된다**는
신호로 받았다.

| 원 패턴 | 적용 | 구현 위치 |
|---|---|---|
| Analyzer — 그래프 구축 | 화면↔트랜잭션↔함수↔SQL 그래프를 DB로 구축 | `nctrid_graph.py`, `NCTRID_MAP` |
| Planner — 계획을 **파일로 고정** | 코드 생성 **전에** `conversion-plan.json` 확정 | `conversion_plan.py`, `plan_all` 노드 |
| Translator | 포팅 노드 | `port_one_screen_method_node` |
| Validator — Translator와 분리 | 별도 모듈 | `validators.py` |
| 무거운 정적분석기 대신 경량 파서 | CodeQL류 대신 lxml + 경량 Java 파서 | `java_ast.py`, `converters.py` |

**기각한 것 — Analyzer의 "타 언어 관용 라이브러리 대체" 탐색.** ReCodeAgent의 Analyzer는 대상
언어의 관용적 라이브러리를 찾는 게 핵심인데, 이 프로젝트는 **닫힌 집합(NEXCORE API)을 결정론적
템플릿으로 치환**하는 문제라 해당이 없다. 범용성을 명목으로 안 쓰는 기능을 만들지 않았다.

## 3. MatchFixAgent / ACToR — 이 프로젝트의 최대 차용점

멘토 코멘트가 "가장 중요한 차용 포인트"로 꼽은 항목이고, 실제로도 그랬다.

- **검증기를 변환기와 독립 모듈로 설계** → 나중에 변환기를 바꿔도 검증 자산이 살아남는다.
- **판정자를 따로 둔다** → 생성한 쪽이 스스로 채점하지 않는다.
- ACToR의 시사점: 적대적 루프가 기저 변환기와 독립적이라 **기존 변환기 위에 얹을 수 있다**.
  이 프로젝트도 "1차 변환 파이프라인"과 "검증·개선 루프"가 분리돼 있어, 다른 전환 프로젝트에
  검증 루프만 재활용할 수 있다.

**구현**: `validate_all → repair_gate → port_one_screen_method(수리 프롬프트) → splice_all →
validate_all` 순환. **LLM이 포팅한 메서드에 귀속된 BLOCKER만** 대상이고(규칙 기반 생성물 제외),
라운드 상한이 있다.

**이 루프를 만들며 찾은 기존 결함 2건**:
1. `splice_ported_method()`가 PORT 마커를 지워서 **수리 결과가 조용히 버려졌다**.
2. `_check_brace_balance()`가 파일 전체 스택 방식이라 **어느 메서드가 깨졌는지 알 수 없었다** —
   가장 흔한 BLOCKER인 중괄호 오류가 수리 루프에 아예 안 잡히고 있었다.

**정직한 기대치**(@docs/03-kickoff-plan.md 2026-09-04 자기 비판): 수리 루프는 **정적 검증만**
피드백으로 쓰므로 AlphaTrans 기준 이미 96.4%였던 *문법* 쪽만 개선하고, 정작 문제인 *기능 동등성*
쪽은 못 건드린다. 그래도 만드는 과정에서 위 결함 2건을 찾았으므로 순효과는 남았다.

## 4. RepoTransAgent — Reflection은 채택, RAG는 연기

| 항목 | 판단 |
|---|---|
| Reflection 루프 + **재시도 상한 2~3회** | **채택**. 상한이 없으면 자율 탐색이 된다 |
| 유사 화면 벡터 검색 → few-shot 주입 (RAG) | **연기**. 파일럿 결과물이 코퍼스가 되므로 파일럿이 먼저다 |
| 화면 유형별 프롬프트 분기 | **부분** — 계층별(F / Api)로는 분기하지만 유형별은 미착수 |

**RAG를 "구현했다"고 말하지 않는다.** 벡터 DB도, 임베딩 호출부도 없다. `llm_gateway.py`에
`embed()` 함수가 있지만 **호출하는 곳이 하나도 없다**(grep 0건). 산출물·발표에 RAG를 구현 기능으로
적지 않는다.

## 6. AWS Transform — Refactor / Reimagine 이원화

"1,416개를 한 가지 방식으로 처리하지 말라"가 핵심 시사점이다.

**적용하되 자동 배정하지 않는다.** `conversion_plan.py`가 트랙을 항상 `UNDECIDED`로 두고
`track_signals`에 판단 근거만 채운다(원본 컴파일 가능 여부, 미지원 DB 동사 유무 등).
**트랙 결정은 사람 몫**이라는 것이 CLAUDE.md와 Phase 3의 명시적 규정이다.

실제로 이 신호가 작동한 사례: `track_signals.as_is_unbalanced_braces`가 `F.java: 14`를 잡아
"원본이 그대로는 컴파일 안 됨"(= Reimagine 후보 기준)을 자동 표시했다.

> 멘토 코멘트의 지적 그대로다 — "확장성 제약으로 기능 추가에 한계"는 Refactor로는 안 풀린다.
> 그대로 옮기면 제약도 같이 옮겨진다. 이것이 @docs/weekly 향후 확장의 **표준화 리뷰 축**이
> 필요한 이유다.

## 7. C2SaferRust / EvoC2Rust — 하이브리드 원칙

## 8. 벤치마크 계열 — 측정 없이 개선을 말하지 않는다

RepoTransBench / CRUST-Bench가 그랬듯 **내부 벤치마크를 먼저 만들어야 개선 여부를 측정할 수
있다**. 그전까지 이 프로젝트의 탐지 기능은 "돌려보니 N건 나왔다"까지만 말할 수 있었다 — 정답을
몰라 그 N건이 맞는지, 놓친 게 몇 건인지 말할 수 없었다.

| 측정 수단 | 구현 | 실측 |
|---|---|---|
| 정답키 대조 채점 | `benchmark.py` | 원본 결함 **10/10**, 오탐 0건 (보강 전 5/10) |
| 중복 탐지 채점 | `benchmark.py` | Type-1 50%/오탐 0% · Type-2 100%/오탐 48% |
| **사람 수정 라인 비율** | `review.py` (status/open/measure/accept) | **0.20%** — AI 리뷰어 1차 기준 하한값 |
| 종합 점수화 | `scorecard.py` | **80.9 / 100** |

멘토 §H가 "가장 중요한 대리 지표"로 꼽은 것이 사람 수정 라인 비율이다. 측정 함수만 있고 **절차**가
없어 값이 4.34% → 15.3% → 4.34%로 오갔던 것을 `review.py`로 해소했다 — `open`이 기준선 해시를
박아두고, 생성분이 바뀌면 **미측정**으로 표시한다.

## 9. Tree-of-Thoughts — 채점자를 바꿔서 차용

일반적인 ToT의 약점은 **모델이 자기 가지를 자기가 평가**한다는 것이다. 이 프로젝트에는 이미
결정론적 검증기가 있으므로 그 약점을 피할 수 있다.

1. BLOCKER 1건마다 서로 다른 방침(`최소수정` / `계약우선`)으로 후보 N개를 **병렬 생성**
2. 후보마다 실제로 splice한 **사본**을 만들어 `validate_screen()` 실행
3. 그 메서드에 귀속된 **잔여 BLOCKER 수로 채점**, 동점이면 원본에서 덜 벗어난 쪽
4. 채택·탈락 근거를 로그에 남김

**실측에서는 두 후보 모두 0건이라 결과가 바뀌지 않았다** — 가지치기가 이번엔 수정을 *확인*했을
뿐 개선하진 않았다. 후보가 갈릴 때 효과가 나는 구조이며, 이 사실을 그대로 보고한다.

## 10. MCP — 자율성이 아니라 창구로

MCP는 **Model Context Protocol**이다. 핵심 가치는 모델이 도구를 동적으로 고르는 것인데, 그건
"자율 탐색형 에이전트를 만들지 않는다"는 이 프로젝트의 원칙과 정면으로 충돌한다. 그래서 도입하되
**표면을 갈랐다**.

| 대상 | MCP 노출 | 이유 |
|---|---|---|
| 변환 실행 | **안 함** | 승인 게이트를 우회할 경로를 열지 않는다 |
| 분석 조회 | **함** | 부작용 없는 결정론적 그래프 조회. 답에 근거를 붙일 수 있다 |

노출 도구 4종(영향도 역추적 / 미사용 함수 / 중복 함수 / 트랜잭션 매핑)은 전부 조회이며, 모든
응답에 한계 문구를 함께 실어 보낸다. `agents/mcp_smoketest.py`가 **실제 MCP 클라이언트로 stdio
연결해** `list_tools`/`call_tool`을 프로토콜 너머로 확인한다 — 이 과정에서 설치된 SDK가 2.x라
1.x 방식으로는 서버가 뜨지도 않는다는 걸 발견해 고쳤다. **"만들었다"와 "붙여봤다"는 다르다.**

## 11. 의도적으로 기각한 것

| 기각 | 이유 |
|---|---|
| **TransCoder류 학습 기반 변환** | 병렬 데이터가 없고 규칙성이 높다. 모델을 학습시킬 이유가 없다 |
| **완전 자율 탐색 에이전트(SWE-agent류)** | 1,416회 반복되는 작업이므로 고정 파이프라인이 자율성보다 낫다. 탐색 비용 대비 효용이 낮다 |
| **범용 다국어/프레임워크 전환기** | NEXCORE→Spring 단일 쌍에 특화하는 게 훨씬 효율적이다 |
| **Verdict를 별도 아티팩트로** | `handoff_report.py`가 이미 같은 역할을 한다. 승인 게이트 자체가 사실상의 Verdict 단계다. 새로 만들면 "이미 있는 BLOCKER 집계를 다른 이름으로 한 번 더 세는" 것에 그친다 |
| **javac 에러를 수리 루프에 피드백** | 수리 루프가 거의 안 걸리는 게 실측이고, Maven이 트리 전체를 빌드해 라운드마다 수 분이 걸린다. 비용 대비 효용이 나쁘다 |

## 12. 이 프로젝트가 선행 연구에 더한 것

차용만 있는 게 아니라, 참조한 연구들이 **다루지 않았거나 전제로 깔고 있던 것**을 이 프로젝트가
직접 다뤄야 했던 지점이 있다.

1. **원본 결함을 정상 입력으로 취급한다.** 참조한 연구는 대체로 컴파일되는 원본을 전제한다.
   이 프로젝트의 실제 AS-IS는 중괄호 누락·XML 태그 불일치·SQL 문법 오류를 갖고 있다. 고치지
   않고 **보존한 채 검출·표시**하며, `ORIGINAL_BUG`으로 도구의 실패와 구분한다.
2. **테스트가 없는 레포에서 기능 동등성을 측정했다.** AlphaTrans/ReCodeAgent가 기존 테스트로
   검증하는 자리를, 최소 실행 하네스(`equivalence_test.py`)로 대신했다. 필요한 건 애플리케이션
   기동이 아니라 F 메서드를 부를 최소 환경이었고, AS-IS가 쓰는 프레임워크 API는 10개 남짓의
   닫힌 집합이었다.
3. **ToT의 채점자를 결정론적 검증기로 교체했다**(§9).
4. **MCP를 자율성 부여가 아니라 조회 창구로 썼다**(§10).
5. **표본 1건짜리 가정을 코퍼스 전수 확인으로 뒤집는 절차를 만들었다.** "P는 순수 위임"이라는
   설계 문서의 서술이 표본 1건 근거였고, 30화면 전수 확인 결과 30/30이 권한 게이트를 갖고
   있었다. 이 발견이 Api 계층 0/9 → 페이로드 9/9로 이어졌다.
